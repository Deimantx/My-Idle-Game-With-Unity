# 04 Item Framework

Version: 1.0
Status: Draft

---

# Purpose

This document defines the structure, behavior, and rules that every item in the game must follow.

Every item should follow this framework unless explicitly designed otherwise.

The goal is to ensure every item behaves consistently across inventory, crafting, combat, shops, professions, companions, equipment, and future systems.

---

# Design Goals

Every item should:

- Have a clear purpose.
- Be easy to understand.
- Support at least one gameplay system.
- Remain useful whenever possible.
- Be expandable for future updates.
- Be fully data-driven.

Avoid creating items that exist only as filler.

# Consumable Types

Consumables are items that are used or activated.

Current consumable types:

Food

Potions

Elixirs

Food:

Provides short-duration buffs.

Examples:

Damage bonus

Defense bonus

Health regeneration

XP gain

Profession efficiency

Potions:

Provide instant or short-term effects.

Examples:

Restore health

Restore devotion

Emergency healing

Elixirs:

Provide stronger temporary buffs.

Examples:

Attack speed

Critical chance

Healing received

Elemental resistance

Consumable rules should remain consistent with the Combat Framework.

# Stack Rules

Maximum Stack Size

Default behavior:

Consumables are stackable.

Crafting materials are stackable.

Currencies are stackable.

# Item Database

Every item should exist inside the Item Database.

Items should never be hardcoded.

Gameplay systems should reference Item IDs instead of creating duplicate data.

Every equipment item should also exist as an item in the Item Database.

Equipment-specific behavior is defined in the Equipment Framework.

---

# Technical Rules

Every item should be data-driven.

Item behavior should not be hardcoded.

Icons should be assigned through data.

Descriptions should be editable without code changes.

Every system should reference the same item data.

Item IDs should remain stable after release to avoid breaking save files.
